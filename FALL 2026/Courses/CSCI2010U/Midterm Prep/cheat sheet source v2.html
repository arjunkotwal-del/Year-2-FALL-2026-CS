A3. JAVA BASICS FOR NON-CODERS

  • Array: boxes numbered from 0. int[] a={5,2,9,2}; a[0]=5, a.length=4 (no brackets), last index = a.length-1 = 3. Asking a[4] crashes.
  • String: s.length() (with brackets), s.charAt(i) = letter at i (starts 0), s.substring(1) = from index 1 to end ("hello"→"ello"), s.substring(1,3) = index 1 up to but NOT including 3 ("el"). s1.compareTo(s2): negative if s1 comes before s2, 0 equal, positive after. Case matters ("Level" differs from "level").
  • n % 10 = last digit (5072 % 10 = 2). n / 10 = drops last digit (5072 / 10 = 507, whole-number division).
  • count++ = add 1. i-- = subtract 1. == compares, = assigns. && and, || or, != not equal. countdown(--i) subtracts 1 FIRST then passes it.
  • javac Foo.java = compile source to Foo.class (bytecode). java Foo = run main in Foo.class (JVM). Compile after every edit. public static void main(String[] args): public = JVM can call it, static = no object needed, void = returns nothing, args = command-line words.
  • import java.util.Arrays; then Arrays.toString(a) prints [4, 3, 5]. Printing an array directly gives garbage like [I@251a69d7. Arrays.sort(a) sorts. java.lang (System, Math, String) is auto-imported.
  • Passing to methods: primitives (int, double) = a COPY. Arrays/objects = a copy of the REFERENCE, so the method changes the SAME array. That is why bubble sort needs no return value.
  • Compile error (javac says no): missing ;, wrong type, method does not exist, new on an abstract class, private field used outside its class, abstract method not implemented, Manager m = new Employee(). Runtime error (crashes while running): ArrayIndexOutOfBoundsException, IndexOutOfBoundsException (list), StackOverflowError (recursion with no base case).

Swap needs a temp (else value lost)

static void swap(int[] A, int j, int k){
  int temp = A[j];
  A[j] = A[k];
  A[k] = temp; }

Bubble sort (L1/L2)

for (int i = A.length-1; i > 0; i--) // i fixed
  for (int j = 0; j < i; j++)        // j moves
    if (A[j+1] < A[j]) swap(A, j, j+1);
// n-1 passes; compares: n-1, n-2, ..., 1
// after pass k the last k are locked
// descending: use A[j+1] > A[j]
// {5,2,4,1}: 2541 | 2451 | 2415 (5 locked)
//  pass2: 2415 | 2145 (4 locked)  pass3: 1245

Linear search (L6)

for (int i = 0; i < A.length; i++)
  if (A[i] == val) return i;
return -1;       // best O(1), worst O(n)

Binary search (L10) - array MUST be sorted

bs(a, val, low, high):
  if (low > high) return NOT_FOUND;
  int mid = (low + high)/2;
  if (val == a[mid]) return mid;
  else if (val < a[mid])
    return bs(a, val, low, mid-1);
  else
    return bs(a, val, mid+1, high);
start: bs(a, val, 0, a.length-1)  O(log2 n)
find 5 in {1,3,5,7,9,11,13}:
 l0 h6 m3=7 | l0 h2 m1=3 | l2 h2 m2=5 found

Array insert / delete (L10), O(n) worst, O(1) best

insert(a, idx, val):
  for (int i=a.length-1; i>idx; i--)
    a[i] = a[i-1];     // shift RIGHT, from the end
  a[idx] = val;
delete(a, idx):
  for (int i=idx+1; i<a.length; i++)
    a[i-1] = a[i];     // shift LEFT
  a[a.length-1] = GAP;
worst idx=0 O(n), best idx=last O(1)

A5. BIG-O RECIPE

  • No loop / fixed steps = O(1). One loop 0..n = O(n). Loop inside loop (both to n, or inner bounded by outer) = O(n^2). Counter halved or doubled each step = O(log n) (log base 2). Two loops one after the other = ADD, keep the biggest: n + n = O(n).
  • Divide-and-conquer with linear combine (merge sort style) = O(n log n). Nested n*n*n = O(n^3).
  • Drop constants and small terms: 6n^2+30n+11 = O(n^2). 3+5n^2+7n^3 = O(n^3).
  • Loop header test runs ONE MORE time than the body: for(i=0;i<n;i++) header n+1, body n.
  • Comparing all pairs: (n-1)+(n-2)+...+1 = n(n-1)/2 = O(n^2).
  • Growth, slow to fast: 1, log n, sqrt n, n, n log n, n^2, n^3, 2^n, n! 2^n and n! are impractical except tiny n.

    A6. RECURSION FACTS (L7, Lab 4)

    • Recursion = defining something in terms of itself; a method that calls itself. Needs BASE CASE (a conditional, first statement, has a return, ends the chain) and RECURSIVE CASE (calls itself on a SMALLER problem so it moves to the base). Missing base case or no progress = StackOverflowError.
    • Calls are stored on the call stack; each call keeps its own variables; a return removes it and gives the value to its caller. Overhead exists. Iterative is the default; use recursion if the problem is naturally recursive (TOH recursive, factorial iterative). Every recursive solution can be iterative.
    • Solve with recursion: write base case first, think of smaller same-shaped subproblems, trust the call, combine the result. A loop stopping test = the recursive base case. String is empty OR a char + another string; a list is a basic object OR an item + the rest.

    B1. OOP VOCABULARY AND FACTS (L3)

    • Class = blueprint/template. Object / instance = a real thing made from it (new). Cookie cutter vs cookies. Instantiate = make an instance.
    • Every object has STATE (fields: what it HAS), BEHAVIOUR (methods: what it DOES), IDENTITY (what makes it unique even with same state, set by Java; Object.equals). Members = fields + methods.
    • Find classes: nouns = classes, verbs = methods (oven, cutter, baker; bake, cut, taste). Good class candidate: something with many instances that each have state + actions (wheel, window, engine, radio).
    • Encapsulation = hide data. Fields private, access through public methods (getters read: getName(), setters write: setBonus()). State change only through a method. final = cannot change. this = the current object (this.name = name). Java catches errors at COMPILE time (Python mostly at runtime).
    • Constructor: same name as the class, no return type, runs on new. All non-static classes need one.
    • Inheritance = subclass gets superclass fields/methods. Keyword extends. Test: "is a". Manager IS AN Employee so Manager extends Employee. NEVER the reverse. Inheritance flows general to specific only: Manager can do all Employee does plus more; Employee cannot call setBonus.
    • "Superclass" does NOT mean better. Subclass can extend (add) and override (redefine). UML: arrow from subclass up to superclass; italics = abstract.

    B4. ALGORITHMS AND ANALYSIS (L1, L6, L8, L9)

    • Algorithm = finite (ends), deterministic (same input same output), effective, implementation (abstract enough for any language, every step precise). Pseudocode = for humans, language-free, skips boilerplate. Recipe analogy. al-Khwarizmi c.800 CE; formalised 1930s (Turing, Church).
    • T(n) = number of basic steps for input size n. Each pseudocode line costs a constant c_i; end and comments not counted. Linear search: T = c1(t+1) + c2 t + c3 + c4. Best case (first spot, t=1) = constant O(1). Worst case (missing, t=n) = an + b = linear O(n).
    • Best = shortest run, worst = longest run, average (not covered). Course uses worst case: it is an upper-bound guarantee and it happens often (searching for something absent).
    • BIG-O definition: f(n)=O(g(n)) if there exist positive constants c and n0 with 0 <= f(n) <= c*g(n) for all n >= n0. g is an UPPER bound. O(g) is a SET of functions. c and n0 must be positive (not 0). Example: 3+5n^2+7n^3 <= 15n^3.
    • Big-O is a notation; worst case is a type of input; Big-O can describe best, worst or any case.
    • Class challenge for 3+5n+18n^2: O(n) FALSE, O(n^2) TRUE, O(n^3) TRUE; 3^n=O(n^3) FALSE; n^3=O(3^n) TRUE.

    B6. LISTS (L11)

    • A List = finite, ordered collection of elements of ONE type. Ordered = each has a position, NOT sorted by value. Empty = no elements. Head = start, tail = end. Sorted list = ascending values; unsorted = no relationship.
    • Interface says WHAT (requirements), implementation says HOW (unsorted list search = linear, sorted = binary). Plan for stacks, queues, lists: interface, array version, linked-list version.
    • Our List<T> methods: add(T) head, add(T,int index) middle, addLast(T) tail, get(int), isEmpty(), size(), toString().

    B8. ONE-LINE ANSWERS FOR "EXPLAIN WHY"

    • Why must a duration EQUAL to the target count? "At least" means greater than OR equal, so use >=.
    • Why does increment() inside the override call itself? Without super. Java calls the current class, which is the override, forever. super.increment() calls the superclass version.
    • super(name) vs super.increment(): the first is the constructor call that sets the superclass private state (first line only); the second calls the superclass version of an overridden method.
    • Why does new Person("x") not compile? Person is abstract, so it cannot be instantiated, even though it has a constructor.
    • Why must a concrete class implement every abstract method? Otherwise the object would have a method with no body.
    • How does Comparable help Arrays.sort? sort calls compareTo on the elements to decide the order; implementing it supplies that rule. implements vs extends: extends inherits ONE class; implements promises to write the interface methods and a class can have many.
    • Loop stop vs recursive base case: both are the condition where the work ends, and each step must move toward it (n/10 reaches 0, string gets shorter).
    • Why does a mismatch return false immediately (palindrome)? One differing pair of outer characters already proves it is not a palindrome.
